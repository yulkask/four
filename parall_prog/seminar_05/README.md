# Семинар 5. Метод Гаусса (OpenMP)

## Сборка и запуск (из папки `parall_prog`)

```bash
clang++ -O2 -Xpreprocessor -fopenmp -I/opt/homebrew/opt/libomp/include \
    -L/opt/homebrew/opt/libomp/lib -lomp seminar_05/gauss.cpp -o seminar_05/gauss
./seminar_05/gauss                      # системы из seminar_05/systems.txt + замеры
python3 seminar_05/make_excel.py        # results/seminar5_gauss.xlsx, нужен openpyxl
```

## Ввод

Матричный ввод из [systems.txt](systems.txt): имя системы и порядок n, затем n строк
расширенной матрицы `[A | b]`. В системе в) свободный член перенесён вправо:
2x₁ + 3x₂ + 1 = 0 → 2x₁ + 3x₂ = −1.

## Алгоритм

Прямой ход, k = 0..n−2, i = k+1..n−1:

1. l_ik = a_ik / a_kk
2. a_ij = a_ij − l_ik · a_kj, j = k..n−1
3. b_i = b_i − l_ik · b_k

Обратный ход, k = n−1..0:

4. x_k = (b_k − Σ_{i>k} a_ki · x_i) / a_kk

`gauss_serial` — последовательная версия, `gauss_omp` — параллельная. Параллельная
область создаётся один раз. На каждом шаге k цикл по строкам i (формулы 1–3)
распределяется между потоками через `omp for`. Неявный барьер в конце `omp for`
гарантирует, что строка k+1 обновлена до начала следующего шага.

Обратный ход выполняет один поток (`omp single`). Вариант из лекции с
`omp for reduction(+:s)` для каждого k ставит 3 барьера на каждое неизвестное
при O(n) работы между ними и на этой машине медленнее последовательного:

| n = 1000 | 1 поток | 2 | 4 | 8 |
|---|---|---|---|---|
| обратный ход с редукцией, с | 0.0003 | 0.015 | 0.029 | 0.079 |

## Корни систем

| | Корни | | | Корни |
|---|---|---|---|---|
| а | (2; 3) | | е | (0; 3; −3) |
| б | (−1; 2) | | ж | (2; 1; 0) |
| в | (1; −1) | | з | (1; 0; −1) |
| г | (2; −1; 1) | | и | (−1; 0; 2) |
| д | (4; 5; −3) | | к | (1; −1; 2) |

Последовательная и параллельная версии дают одинаковые корни, невязка
max|A·x − b| ≤ 2.6·10⁻¹². Ответы а), б), в) совпадают с контрольными.

## Ускорение и эффективность

Случайные коэффициенты 1..100 (как в лекции) с диагональным преобладанием, чтобы
метод без выбора ведущего элемента был устойчив. Невязка на всех размерах ≤ 1.3·10⁻¹².
Apple M4: 4 производительных + 6 энергоэффективных ядер, поэтому потоки 1, 2, 4, 8.
S = T_посл / T_p, E = S / p.

**Выводы.**
- Прямой ход ограничен пропускной способностью памяти: на каждое умножение
  приходится чтение и запись элемента матрицы. Матрицы 2000×2000 (32 МБ) и
  4000×4000 (128 МБ) не помещаются в кэш, и на каждом шаге k оставшаяся часть
  матрицы заново читается из памяти. Поэтому чем больше n, тем ниже ускорение.
- На 1000×1000 (8 МБ, матрица почти целиком в кэше) ускорение лучшее — 2.25 на 4 потоках.
- На 8 потоках 4 потока работают на медленных энергоэффективных ядрах, а
  остальные ждут их на барьере после каждого из n шагов.
- Обратный ход O(n²) последовательный, но занимает < 1 % времени.
