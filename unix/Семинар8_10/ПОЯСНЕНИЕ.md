## Строки 11–21. Константы и структура результата

```c
13  #define EPS 1e-17
```
Относительная точность суммирования рядов. Цикл останавливается, когда член
ряда меньше `EPS × сумма`. Тип `double` хранит около 16 значащих цифр, поэтому
дальнейшие слагаемые уже не меняют сумму.

```c
15  enum { CHILD_PI = 0, CHILD_EXP = 1, NCHILD = 2 };
```
Именованные номера потомков: потомок 0 считает π, потомок 1 считает exp.
`NCHILD = 2` — общее число потомков, оно используется как размер массивов и
граница циклов.

```c
18  struct result {
19      double value;
20      long terms;
21  };
```
Блок данных, который потомок пишет в канал: вычисленное значение и число
использованных членов ряда. Передавать структуру одним блоком удобнее, чем
отправлять два числа по отдельности.

> В строке 17 комментарий начинается с `//`, а заканчивается на `*/`. Ошибки
> компиляции это не вызывает, но лишние `*/` в конце строки лучше убрать.

## Строки 23–34. Флаги и обработчик сигналов

```c
25  static volatile sig_atomic_t got_start = 0;
26  static volatile sig_atomic_t got_stop = 0;
```
Глобальные флаги «пришёл сигнал старта» и «пришёл сигнал завершения».
- `static` делает переменные видимыми только в этом файле.
- `volatile` запрещает компилятору держать значение в регистре: переменная
  меняется «извне», в обработчике сигнала, и цикл ожидания должен каждый раз
  читать её из памяти.
- `sig_atomic_t` — целый тип, запись в который не может быть прервана
  сигналом на середине.

```c
28  static void on_signal(int sig)
30      if (sig == SIGUSR1) got_start = 1;
32      else if (sig == SIGUSR2) got_stop = 1;
```
Один обработчик на оба сигнала. По номеру `sig` он определяет, какой флаг
выставить. Больше обработчик ничего не делает: из обработчика сигнала нельзя
безопасно вызывать `printf` и большинство других функций, поэтому основная
работа идёт в обычном коде, который проверяет флаги.

Формула: `arctg z = z − z³/3 + z⁵/5 − z⁷/7 + …`, член с номером n равен

| 44 | `z2 = z²` вычисляется один раз и потом используется для перехода к следующей степени |
| 45 | `power` — текущая степень `z^(2n+1)`. При n = 0 это просто `z` |
| 46 | `sum` — накопленная сумма ряда |
| 47 | `n` — номер текущего члена |
| 49 | Бесконечный цикл `for (;;)`, выход из него через `break` |
| 50 | Модуль текущего члена: `z^(2n+1) / (2n+1)` |
| 51–52 | Условие остановки: член пренебрежимо мал по сравнению с суммой. На первом шаге `sum = 0`, условие ложно, и первый член всегда добавляется |
| 53 | Знак чередуется: при чётном n член прибавляется, при нечётном вычитается |
| 54 | Следующая степень: `z^(2n+1) · z² = z^(2n+3)`. Функция `pow` не нужна |
| 55 | Переход к следующему номеру |
| 57 | Число сложенных членов **добавляется** (`+=`) к счётчику, потому что функция вызывается дважды и оба вызова пишут в один счётчик |

## Строки 61–67. Число π по формуле Мэчина

```c
64  *terms = 0;
65  return 16.0 * arctan_series(1.0 / 5.0, terms)
66       - 4.0 * arctan_series(1.0 / 239.0, terms);
```
`π = 16·arctg(1/5) − 4·arctg(1/239)`. Счётчик сначала обнуляется, потом оба
вызова прибавляют к нему свои количества: 12 членов для 1/5 и 4 для 1/239.
Аргументы маленькие, поэтому ряды сходятся быстро. Ряд Лейбница
`1 − 1/3 + 1/5 − …` для такой же точности потребовал бы миллиарды членов.

## Строки 69–95. Ряд для exp(−x²/2)

Формула: `e^(−t) = 1 / (1 + t + t²/2! + t³/3! + …)`, где `t = x²/2`.

| Строка | Что делает |
|---|---|
| 83 | `t = x²/2`. Всегда `t ≥ 0`, поэтому все члены ряда положительны |
| 84 | Первый член ряда `t⁰/0! = 1` |
| 85 | Сумма уже содержит этот первый член |
| 86 | Номер шага n (он же делитель в факториале) |
| 88 | Цикл идёт, пока последний член заметен на фоне суммы |
| 89 | Следующий номер шага |
| 90 | **Ключевая строка задания.** Новый член вычисляется из предыдущего: `tⁿ/n! = (tⁿ⁻¹/(n−1)!) · t / n`. Факториал отдельно не считается: на каждом шаге член умножается на `t` и делится на `n` |
| 91 | Член прибавляется к сумме |
| 93 | Возвращает число членов через указатель |
| 94 | Возвращает `1 / e^t = e^(−t)` |

Почему не суммируется знакопеременный ряд `1 − t + t²/2! − …` напрямую: при
`x = 10` (`t = 50`) его члены доходят до 10²⁰, а ответ равен примерно 10⁻²².
При вычитании таких больших близких чисел от точности ничего не остаётся. Ряд
с положительными членами вычитаний не содержит.

### Блокировка сигналов (228–231)

| Строка | Что делает |
|---|---|
| 228 | Пустой набор сигналов |
| 229–230 | Добавляет в него `SIGUSR1` и `SIGUSR2` |
| 231 | Блокирует их. Прежняя маска сохраняется в `oldmask` |

Зачем это нужно. Если родитель пошлёт `SIGUSR1` раньше, чем потомок дойдёт
до ожидания, незаблокированный сигнал отработает впустую, и потомок уснёт
навсегда. Заблокированный сигнал не теряется: он ждёт («отложен»), пока потомок
не вызовет `sigsuspend(&oldmask)`, где сигналы разрешены. Маска сигналов
наследуется при `fork()`, поэтому потомки стартуют уже с блокировкой.

### Создание каналов (234–239)

`pipe(fds[i])` создаёт канал и записывает в `fds[i][0]` дескриптор для чтения,
а в `fds[i][1]` — для записи. Каналы создаются до `fork()`, чтобы потомки
унаследовали дескрипторы.

### Старт потомков (276–280)

`kill(pid[i], SIGUSR1)` посылает потомку сигнал старта. Несмотря на название,
`kill` не обязательно убивает процесс: он просто посылает указанный сигнал.
Оба потомка получают сигнал почти одновременно и считают параллельно.

### Чтение результатов (283–290)

`read_full` блокирует родителя, пока потомок не запишет свою структуру.
Синхронизация получается сама собой: родитель не продолжит, пока данных нет.
При ошибке сбрасывается флаг `ok`. После чтения канал закрывается.

## Порядок событий во времени

```

────────                         ─────────────        ───────────────
sigaction, sigprocmask(BLOCK)
pipe × 2
fork ─────────────────────────►  sigsuspend (спит)
fork ──────────────────────────────────────────────►  sigsuspend (спит)
close концы записи
kill SIGUSR1 ─────────────────►  считает π
kill SIGUSR1 ──────────────────────────────────────►  считает exp
read канал 0 (ждёт) ◄─────────── write
read канал 1 (ждёт) ◄──────────────────────────────── write
                                 sigsuspend           sigsuspend
kill SIGUSR2 ─────────────────►  exit(0)
kill SIGUSR2 ──────────────────────────────────────►  exit(0)

```
