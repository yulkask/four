# Семинар 12: очереди сообщений System V (`sys/msg.h`)

Проверка числа на простоту двумя программами, которые обмениваются
сообщениями через очередь.

- `common.h` — формат сообщения, типы сообщений и ключ очереди;
- `ask.c` — первая программа: читает число, кладёт в очередь, ждёт ответ;
- `check.c` — вторая программа: создаёт очередь, проверяет числа, отвечает.

Сборка и запуск (в двух терминалах, из этой папки):

```sh
cd unix/Семинар_12
make
./check     # терминал 1, запускается первым, выход — Ctrl+C
./ask       # терминал 2, выход — Ctrl+D (можно запустить несколько)
```

## Сообщение

```c
struct message {
	long mtype;               // MT_REQUEST (1) или pid получателя
	pid_t pid;                // кто спрашивает
	unsigned long long value; // число
	int verdict;              // NONE (0 и 1) / PRIME / COMPOSITE
};
```

В `msgsnd`/`msgrcv` передаётся размер без поля `mtype`:
`sizeof(struct message) - sizeof(long)`.

## Как идёт обмен

1. `ask` отправляет сообщение с типом `MT_REQUEST = 1`, своим pid и числом.
2. `check` вызывает `msgrcv(..., MT_REQUEST, 0)` и получает только запросы.
   Проверяет число и отправляет то же сообщение обратно с типом,
   равным pid спросившего, и заполненным `verdict`.
3. `ask` вызывает `msgrcv(..., getpid(), 0)` и блокируется, пока в очереди
   не появится сообщение именно с его pid.

Запросы и ответы лежат в одной очереди, но по типу каждый процесс выбирает
только своё. Поэтому `ask` можно запустить в нескольких терминалах
одновременно, и ответы не перепутаются. В примере ответ всегда шёл
с типом 2, и при двух клиентах ответ мог забрать не тот.

## Отличия от примеров `msgserv.c` / `msgclient.c`

- Ключ — `ftok("common.h", 'Q')` вместо числа 666.
- `ask` вызывает `msgget` без `IPC_CREAT`. Если `check` не запущен,
  выводится «Очереди нет: сначала запустите ./check».
- В `check` обработчик ставится через `sigaction` только на SIGINT, SIGTERM
  и SIGHUP. Он лишь выставляет флаг. `msgrcv` прерывается с `EINTR`, цикл
  заканчивается, и очередь удаляется `msgctl(IPC_RMID)` в `main`.
  В примере `signal` ставился на сигналы 0–19 подряд, включая SIGKILL и
  SIGSTOP, которые перехватить нельзя, а `exit` вызывался из обработчика.
- Проверяются ошибки всех вызовов. Если очередь удалили, пока `ask` ждёт
  ответ, `msgrcv` вернёт `EIDRM`, и `ask` завершится с сообщением.
- Добавлены `#include <unistd.h>` и `int main`: без них пример не
  собирается современным компилятором.

## Проверка на простоту

Делители 2, 3 и далее `6k±1` до `√n`. Условие цикла `i <= n / i`, а не
`i * i <= n`, чтобы не было переполнения у чисел около 2⁶⁴. Ввод
проверяется через `strtoull`: отрицательные числа, буквы и слишком большие
значения отклоняются.

## Пример

```
$ ./check
Ожидание чисел в очереди (Ctrl+C — выход)...
От pid 50819 получено 91 -> составное
От pid 50821 получено 13 -> простое
От pid 50819 получено 1 -> ни то, ни другое
^C
Очередь удалена
```

```
$ ./ask
Введите число (Ctrl+D — выход): 91
Число 91 отправлено в очередь
Ответ из очереди: 91 — составное

Введите число (Ctrl+D — выход): 1
Число 1 отправлено в очередь
Ответ из очереди: 1 — ни простое, ни составное
```
