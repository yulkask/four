# Семинар 15–16: RPC, список файлов каталога

Задание: клиент вызывает удалённую процедуру и передаёт имя каталога
на сервере. Сервер возвращает список файлов в этом каталоге.

Основа — частичный пример из `Условие15-16` (`dir.x` и `dir_server.c`).
Рабочая программа лежит в этой папке:

- `dir.x` — описание процедуры для `rpcgen`;
- `dir_server.c` — процедура, которая читает каталог;
- `dir_client.c` — программа, которая вызывает её по сети;
- `Makefile` — сборка.

`rpcgen` по `dir.x` сам создаёт `dir.h`, `dir_clnt.c`, `dir_svc.c` и `dir_xdr.c`.
Их не правят: при следующей сборке они перезаписываются.

## Сборка и запуск

Нужен `rpcbind` (portmapper). Через него клиент узнаёт, на каком порту
слушает сервер. На macOS служба есть, но по умолчанию не запущена:

```sh
sudo launchctl bootstrap system /System/Library/LaunchDaemons/com.apple.rpcbind.plist
```

На Linux обычно хватает `sudo systemctl start rpcbind`.

Дальше, из этой папки, в двух терминалах:

```sh
cd unix/Семинар15_16
make
./dir_server                 # терминал 1, остановка — Ctrl+C
./dir_client localhost /tmp  # терминал 2, путь каталога на машине сервера
```

`RPC_SVC_FG` в `Makefile` оставлен специально: сгенерированный `main`
без этого флага делает `fork` и уходит в фон.

Пока `rpcbind` не запущен, сервер пишет
`unable to register (DIRPROG, DIRVERS, udp)`, а клиент —
`RPC: Port mapper failure`. Сама процедура каталога проверена отдельно:
для текущего каталога она возвращает те же имена, что `ls -a`.
Чужого каталога нет — код 2 (`ENOENT`), обычный файл вместо каталога —
код 20 (`ENOTDIR`).

## Как проходит вызов

```
dir_client                          dir_server
    |                                    |
    |  clnt_create(хост, DIRPROG, ...)   |  svc_register в portmapper
    |----------------------------------->|
    |  READDIR("имя каталога")           |  readdir_1_svc
    |  XDR-строка по TCP                 |  opendir + readdir
    |<-----------------------------------|
    |  список имён или errno             |
```

1. Сервер при старте сообщает portmapper номер программы `0x20000076`,
   версию 1 и свой порт. Номер из пользовательского диапазона
   `0x20000000–0x3fffffff`, он не пересекается со стандартными службами.
2. `clnt_create` спрашивает portmapper на указанном хосте и открывает TCP.
3. `readdir_1` из `dir_clnt.c` упаковывает строку в XDR и вызывает
   процедуру номер 1. XDR — это единый двоичный формат, порядок байт
   на клиенте и сервере может различаться.
4. Каркас из `dir_svc.c` распаковывает аргумент и вызывает `readdir_1_svc`.
5. Ответ — структура с полем `err`. Ноль означает, что дальше идёт список.
   Ненулевое значение — код `errno`, список в ответ не кладётся.

Имя каталога — путь на сервере. Клиент может запросить `/tmp`, даже если
такого каталога на его машине нет.

## `dir.x`

| Конструкция | Смысл |
|---|---|
| `string nametype<MAXNAMELEN>` | строка не длиннее 255 символов, в C это `char *` |
| `namenode` | имя и указатель на следующий узел |
| `namelist` | указатель на `namenode`, конец списка — `NULL` |
| `union readdir_res switch (int err)` | при `err == 0` передаётся список, иначе поле пустое |
| `READDIR(nametype) = 1` | единственная процедура, номер 1 |
| `= 0x20000076` | номер программы в portmapper |

Список сделан структурой, а не массивом: число файлов заранее неизвестно.
`rpcgen` передаёт такую цепочку как связанный список указателей.

## Сервер, `dir_server.c`

Функция называется `readdir_1_svc`: имя процедуры, номер версии, суффикс
серверной стороны. Так её ждёт сгенерированный каркас.

`result` объявлен `static`. После `return` каркас ещё читает эту память
и упаковывает её в XDR. Локальная переменная к этому моменту уже была бы
уничтожена.

Перед новым успешным ответом предыдущий список снимается через `xdr_free`.
Иначе каждый вызов оставлял бы в куче старые строки. Если прошлый вызов
закончился ошибкой, список уже освобождён вручную, и `xdr_free` не вызывается:
при `err != 0` функция XDR до списка не доходит.

Дальше обычный обход каталога:

- `opendir` не открыл путь — в `err` кладётся `errno`, клиент печатает текст
  через `strerror`;
- на каждое имя `readdir` выделяется узел и копия строки `strdup`;
- указатель `tail` всегда показывает поле, куда записать следующий узел,
  в начале это `&result.readdir_res_u.list`;
- `readdir` вернул `NULL` и `errno != 0` — это сбой чтения, а не конец каталога.

В список попадают все элементы, включая `.` и `..`. `readdir` возвращает
именно элементы каталога, без отдельного отбора «только обычные файлы».

При нехватке памяти уже собранная цепочка освобождается, клиенту уходит
`EAGAIN`. В черновике из условия этот список терялся.

## Клиент, `dir_client.c`

```
./dir_client <хост> <каталог>
```

Строка длиннее `MAXNAMELEN` отвергается до вызова: спецификация всё равно
не дала бы её отправить. `readdir_1` возвращает указатель на свой
статический буфер. Этот указатель освобождать нельзя. `xdr_free` снимает
только строки и узлы, которые заглушка выделила при разборе ответа.
`clnt_destroy` закрывает соединение.

Если сервер не найден или вызов сорвался, текст даёт `clnt_pcreateerror`
или `clnt_perror`. Если процедура выполнилась, но каталог не прочитан,
печатается `strerror` от присланного кода.

## Файлы, которые пишет `rpcgen`

| Файл | Зачем |
|---|---|
| `dir.h` | структуры, номера `DIRPROG` / `DIRVERS` / `READDIR`, прототипы |
| `dir_xdr.c` | упаковка и распаковка строки, узла списка и `readdir_res` |
| `dir_clnt.c` | `readdir_1`: один `clnt_call` с тайм-аутом 25 секунд |
| `dir_svc.c` | `main`, регистрация UDP и TCP, цикл `svc_run`, вызов `readdir_1_svc` |

Приведение `xdr_*` к типу `xdrproc_t` в этих файлах пишет сам `rpcgen`.
У нового clang типы указателей на функции не совпадают, поэтому в
`Makefile` для этого предупреждения стоят `-Wno-...`. На Linux с gcc
программа собирается теми же исходниками.

## Пример `rpc_example`: удалённое время

`rdate.x` описывает программу `1234567` с двумя процедурами.
`BIN_DATE` без аргументов возвращает `time(NULL)`.
`STR_DATE` принимает это число и возвращает строку `ctime`.

`time_svc.c` — серверные процедуры. Результаты `static`, по той же причине,
что и список каталога. `compile.sh` запускает `rpcgen` и собирает клиент
с `rdate_clnt.c`, сервер с `rdate_svc.c`. `clean.sh` удаляет продукты сборки.

В `time_clnt.c` строка `p = &bin_date_1(...)` записана с ошибкой.
`bin_date_1` уже возвращает `long *`, лишний `&` берёт адрес временного
значения. Компилятор такой вызов не собирает. Нужно
`p = bin_date_1(NULL, handle)`. Вызов `str_date_1` ниже записан верно.

Порядок запуска: сначала `./time_svc`, затем `./time_clnt`.
Клиент всегда обращается к `localhost`.

## Черновик каталога в условии

`dir.x` в папке примера совпадает по протоколу с рабочим файлом: тот же
номер программы, та же процедура `READDIR`. `dir_server.c` рядом — шаблон,
который `rpcgen` предлагает заполнить. В нём каталог читается так же,
но нет проверки `strdup`, список при ошибке `malloc` не освобождается,
а в условии `while` стоит присваивание без сравнения с `NULL`.
Клиента в том каталоге нет: его роль выполняет `dir_client.c` этой папки.

## Дополнительные примеры

Это учебные наброски команд Unix. Ниже — что делает каждый файл и где
код расходится с настоящей утилитой.

### `dirlist.c`

Обходит текущий каталог. Имена на `.` пропускает. Для остальных печатает
строку в духе `ls -l`: `d` или `-`, девять прав `rwx`, число жёстких ссылок,
имя пользователя, имя группы, размер, имя файла.

Права берутся из младших 9 бит `st_mode`. Бит `256` (восьмеричное `0400`)
проверяется и сдвигается влево, пока не будут просмотрены все девять.

Имена владельца ищутся через `getpwuid` и `getgrgid`. Если записи нет,
код пытается напечатать числовой id через `sprintf`, но `nuser` и `ngroup`
никуда не указывают. Это неопределённое поведение. Нужен свой массив `char`.
`opendir` и `lstat` тоже не проверяются.

### `fileinfo.c`

`lstat` по пути из `argv[1]` и печать полей `struct stat`: тип, режим
восьмеричным числом, inode, число ссылок, устройство, uid, gid, `rdev`,
размер, время доступа, модификации и смены статуса. Для символической
ссылки `lstat` описывает саму ссылку. Без аргумента обращение к `argv[1]`
некорректно. На macOS для `major`/`minor` нужен `#include <sys/types.h>`,
он в файле есть.

### `free.c`

Только Linux. `sysinfo` заполняет сводку по памяти и свопу, программа
делит байты на 1024 и печатает килобайты: всего, занято, свободно,
разделяемая память, буферы, своп и суммы. Вызов `sysinfo` не проверяется.
Заголовки `linux/kernel.h` и `linux/sys.h` для этого не нужны.
В актуальной структуре размеры заданы в единицах `mem_unit`, этот файл
`mem_unit` не умножает.

### `getopt.c` и `getoptlong.c`

Разбор аргументов командной строки, текст близок к `man getopt`.

Строка `"abc:d:012"`: `-a`, `-b`, `-0`, `-1`, `-2` без значения,
`-c` и `-d` требуют аргумент, он оказывается в `optarg`.
После цикла в `argv[optind]` и дальше лежат обычные аргументы, не опции.
Цифры, пришедшие разными словами `argv`, отмечаются отдельной фразой.

`getopt_long` добавляет таблицу длинных имён: `--add`, `--append`,
`--delete`, `--verbose`, `--create`, `--file`. Если в таблице `val == 0`,
функция возвращает 0 и имя смотрят по `option_index`. `--create` возвращает
`'c'`, поэтому идёт в ту же ветку, что и `-c`.

### `ln.c`

Последние два аргумента — существующий файл и новое имя.
`-s` выбирает `symlink`, без него вызывается `link` (жёсткая ссылка).
`-f` после создания сразу делает `unlink` нового имени, то есть ссылка
уничтожается. У обычного `ln -f` цель удаляется до создания новой ссылки.
Файл использует `bool`, но не подключает `<stdbool.h>`, как программу на C
его не собрать.

### `chown.cpp`

Меняет владельца файла.

- три аргумента: `программа пользователь файл` — uid и основная группа
  этого пользователя;
- четыре аргумента: `программа группа пользователь файл` — группа берётся
  из первого аргумента, пользователь из второго. Это обратный порядок
  относительно привычного `chown пользователь:группа файл`.

Имена переводятся через `getpwnam` и `getgrnam`. Ошибка `chown` (нет файла
или нет прав) печатается текстом, но программа всё равно завершается с кодом 0.
`sys/sysinfo.h` здесь ни при чём и мешает сборке вне Linux. Для ссылки
нужен `lchown`: `chown` меняет файл, на который ссылка указывает.

## `getpagesize`

В `Почитать.txt` одна функция: `getpagesize()` возвращает размер страницы
памяти в байтах. На этой машине страница 16384 байт, на многих других
системах — 4096.
Страница — единица, которыми ядро выдаёт процессу адресное пространство.
К разбору каталога по RPC она не относится; заметка лежит рядом как
справочный материал к примерам про память (`free.c`).
