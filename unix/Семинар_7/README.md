# Семинар 7: регулярные выражения POSIX (`regex.h`)

- `regex.c` — исходный пример: подстановка переменных окружения в строку.
- `words.c` — задание b: слова из текстового файла выводятся через точку.
- `sample.txt` — файл для проверки.

Сборка и запуск:

```sh
cd unix/Семинар_7
make
./regex
./words sample.txt      # или: echo "a b,c" | ./words
```

## a) Исходный пример `regex.c`

Функция `paste_env` ищет в строке шаблон `\$\w+` (знак `$` и имя переменной).
Для каждого совпадения:

1. `regexec` возвращает в `regmatch_t` смещения начала (`rm_so`) и конца
   (`rm_eo`) совпадения относительно переданного указателя `str + offset`.
   К ним прибавляется `offset`, чтобы получить позиции во всей строке;
2. имя без `$` копируется в `buf` и передаётся в `getenv`;
3. если переменная есть, собирается новая строка: часть до `$`, значение
   переменной, часть после имени. Предыдущий буфер освобождается.

Вывод на macOS:

```
SOURCE STRING: $HOME something... $PWD $TERM
match: HOME, rm_so=14, rm_eo=19
match: PWD, rm_so=40, rm_eo=44
match: TERM, rm_so=88, rm_eo=93
FINAL STRING: /Users/yulia something... /Users/yulia/Desktop/four/unix/Семинар_7 $TERM
```

`$TERM` здесь не заменён: при запуске не из терминала этой переменной нет.

Чтобы пример собрался и работал на macOS, в него внесены два изменения:
- удалён `#include <malloc.h>`: такого заголовка на macOS нет, а `malloc`
  объявлен в `<stdlib.h>`;
- к флагам `regcomp` добавлен `REG_ENHANCED`. Без него macOS не распознаёт
  `\w` и `\b`: выражение компилируется без ошибок, но ничего не находит.
  В glibc это расширения GNU, они работают и так, поэтому для Linux
  флаг определяется как `0`.

Недостатки примера (оставлены как есть):
- после замены `offset` увеличивается на длину имени, а не на длину
  подставленного значения. Поиск продолжается внутри вставленного текста;
- `if (pm.rm_so == -1) continue;` зациклился бы: `offset` не меняется;
- `REG_NOTBOL` передаётся и при первом поиске, хотя это начало строки;
- функция возвращает то исходный литерал, то память из `malloc`, поэтому
  освободить результат вызывающий код не может.

## b) `words.c`: слова из файла через точку

Регулярное выражение `\b\w+\b` (в Си — `"\\b\\w+\\b"`): одна или несколько
«словесных» литер (буквы, цифры, `_`) между границами слова.

- Файл читается построчно `getline`. Без аргумента читается `stdin`.
- Для каждой строки `regexec` вызывается в цикле. После совпадения указатель
  сдвигается на `rm_eo`, и поиск продолжается с остатка строки.
- Со второго поиска передаётся `REG_NOTBOL`: остаток — не начало строки.
- Слова одной строки печатаются через `.`, строки без слов пропускаются.
  В конце выводится общее число слов.
- `setlocale(LC_ALL, "")` берёт локаль из окружения. В UTF-8 локали `\w`
  распознаёт кириллицу, в локали `C` русские слова не находятся.
- Ошибки `fopen` и `regcomp` выводятся через `perror` и `regerror`.

Пример:

```
$ ./words sample.txt
Hello.world.This.is.a.test
Регулярные.выражения.b.w.b.слово.целиком
snake_case.CamelCase.и.числа.42.3.14
последняя.строка.без.перевода
Всего слов: 24
```

Из `\b\w+\b` в тексте получились слова `b`, `w`, `b`: обратная косая черта
не входит в `\w`. Число `3.14` разбито на `3` и `14` по той же причине.
