# Семинар 11: разделяемая память System V (`sys/shm.h`)

Проверка числа на простоту двумя программами, которые обмениваются данными
через сегмент разделяемой памяти.

- `common.h` — общая структура в памяти и способ получить ключ;
- `ask.c` — первая программа: читает число, кладёт в память, ждёт ответ;
- `check.c` — вторая программа: проверяет число и записывает результат.

Сборка и запуск (в двух терминалах, из этой папки, порядок любой):

```sh
cd unix/Семинар_11
make
./check     # терминал 1
./ask       # терминал 2
```

## Что лежит в памяти

```c
struct shared {
	atomic_int state;         // EMPTY / REQUEST / DONE / QUIT
	unsigned long long value; // число
	int verdict;              // NONE (0 и 1) / PRIME / COMPOSITE
};
```

Поле `state` показывает, чья сейчас очередь:

| Шаг | Кто | Действие | `state` |
|-----|-----|----------|---------|
| 1 | `ask` | записывает `value` | `EMPTY` → `REQUEST` |
| 2 | `check` | видит `REQUEST`, считает, записывает `verdict` | `REQUEST` → `DONE` |
| 3 | `ask` | видит `DONE`, печатает ответ | `DONE` → `EMPTY` |
| конец | `ask` | на Ctrl+D | → `QUIT`, `check` завершается |

Обе программы «проверяют память» в цикле с паузой `usleep(10 мс)`.
`state` объявлен как `atomic_int`: запись `value`/`verdict` гарантированно
видна другому процессу раньше, чем изменённое состояние. С обычным `int`
компилятор или процессор могли бы переставить эти записи.

## Отличия от примера `shmexample`

- Ключ: `ftok("common.h", 'P')` в обеих программах. В примере вторым
  аргументом был `getpid()` — у каждого процесса свой ключ и свой сегмент,
  и две программы не увидели бы данные друг друга.
- Размер сегмента — `sizeof(struct shared)`, а не 1 КБ под строку.
- `ask` в конце вызывает `shmctl(IPC_RMID)`. Сегмент удаляется, когда от
  него отсоединятся оба процесса; в примере он оставался в системе
  (видно в `ipcs -m`).

## Проверка на простоту

Делители 2, 3 и далее `6k±1` до `√n`. Условие цикла `i <= n / i`, а не
`i * i <= n`, чтобы не было переполнения у чисел около 2⁶⁴. Ввод
проверяется через `strtoull`: отрицательные числа, буквы и слишком большие
значения отклоняются.

## Пример

```
$ ./ask                                   $ ./check
Введите число (Ctrl+D — выход): 91        Ожидание чисел в разделяемой памяти...
Число 91 записано в разделяемую память    Получено 91 -> составное
Ответ из памяти: 91 — составное           Получено 17 -> простое
                                          Получено 1 -> ни то, ни другое
Введите число (Ctrl+D — выход): 17        Первая программа завершила работу
Число 17 записано в разделяемую память
Ответ из памяти: 17 — простое

Введите число (Ctrl+D — выход): 1
Число 1 записано в разделяемую память
Ответ из памяти: 1 — ни простое, ни составное

Введите число (Ctrl+D — выход): ^D
```

Если `check` ещё не запущен, `ask` через секунду пишет «Ждём ответа от
./check...» и продолжает ждать.
