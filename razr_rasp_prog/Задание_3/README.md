# Многопользовательский TCP-чат (C#)

Сервер обслуживает несколько клиентов одновременно. Клиент подключается, отправляет ник, а затем одновременно читает консоль и сокет.

| Папка                  | Что внутри                                     | Кто запускает                 |
|------------------------|------------------------------------------------|-------------------------------|
| `server/`              | TCP-сервер                                     | я                             |
| `КЛИЕНТ_ДЛЯ_ОТПРАВКИ/` | TCP-клиент и инструкция `ИНСТРУКЦИЯ.md`        | трое участников команды       |

## Как устроено

**Сервер** работает в одном потоке на неблокирующих сокетах и `Socket.Select`. В каждой итерации `Select` возвращает сокеты, которые готовы к чтению или записи, поэтому сервер никогда не ждёт конкретного клиента. У каждого клиента есть свой буфер входящих байтов, из которого собираются строки (TCP передаёт поток байтов, а не сообщения), и своя очередь отправки. Если клиент не читает данные и в его очереди накопилось больше 1 МБ, сервер отключает его, чтобы зависший клиент не тормозил остальных. Обрыв соединения, некорректный UTF-8 и слишком длинные строки не роняют сервер.

**Клиент** читает сокет в отдельном потоке и выводит строки сервера как есть. Основной поток читает консоль и отправляет строки на сервер. Ctrl+C и `/quit` штатно закрывают соединение. Если сервер пропал, клиент сообщает об этом и завершается.

## Протокол (согласован в аудитории)

1. TCP, порт `50001`.
2. UTF-8, одна строка = одно сообщение, конец строки `\n` (`\r` перед ним отбрасывается). Пустые строки игнорируются. Максимальная длина строки 1024 байта: более длинные строки обрезаются при отправке.
3. Первой строкой клиент отправляет ник: 1-20 символов, без пробелов и управляющих символов. Ники уникальны без учёта регистра. Если ник некорректен или занят, сервер отправляет `*** error: <причина>` и закрывает соединение. Иначе всем остальным уходит `*** nick joined`.
4. Обычная строка или `/msg текст` рассылается всем, кроме отправителя, в виде `[nick]: текст`.
5. Команды обрабатывает сервер:
   - `/list` отвечает запросившему: `*** online (N): nick1, nick2`;
   - `/nick новый` рассылает всем `*** старый is now known as новый` или отвечает запросившему `*** error: <причина>`;
   - `/quit` отключает клиента;
   - любая другая команда на `/`: `*** error: unknown command`.
6. При отключении (`/quit`, Ctrl+C, обрыв) остальным уходит `*** nick left`.
7. Системные сообщения начинаются с `*** `. Клиент выводит их без разбора.

## Запуск сервера

```sh
cd razr_rasp_prog/Задание_3/server
dotnet run
```

Сервер выведет свои IPv4-адреса, например `Адрес для клиентов: 10.149.2.31 (en0)`. Адрес Wi-Fi-интерфейса (`en0` на macOS) нужно сообщить клиентам. Если macOS спросит, разрешить ли входящие подключения, нажмите «Разрешить». Порт можно сменить аргументом: `dotnet run -- 50002`. Остановка: Ctrl+C (клиенты получат `*** server is shutting down`).

В консоль сервера пишется журнал: подключения, ники, все сообщения, команды и причины отключений.

## Что отправить клиентам

Папку `КЛИЕНТ_ДЛЯ_ОТПРАВКИ` (или архив `КЛИЕНТ_ДЛЯ_ОТПРАВКИ.zip`) и свой IP-адрес. Всё остальное описано в `КЛИЕНТ_ДЛЯ_ОТПРАВКИ/ИНСТРУКЦИЯ.md`.

## Проверка по критериям готовности

1. **3 клиента видят сообщения друг друга.** Трое подключаются, каждый пишет строку, двое других видят `[ник]: текст`.
2. **Ник отображается в сообщениях:** формат `[ник]: текст`, плюс `/nick` и `/list`.
3. **Выход одного клиента не ломает сервер.** Один вводит `/quit`, второй нажимает Ctrl+C, третий закрывает окно терминала. Каждый раз остальные видят `*** ник left`, а сервер продолжает работать: новый клиент подключается без перезапуска.
4. **Сервер не блокируется на одном клиенте.** Один клиент подключается и ничего не вводит (даже ник). Остальные при этом свободно переписываются.
