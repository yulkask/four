# Семинар 7. Реализация протокола SMTP (C#)

| Папка          | Задание | Что внутри                                                        |
|----------------|---------|-------------------------------------------------------------------|
| `cms159.zip`   | 1       | Почтовый сервер Courier (исходный файл, не изменялся)             |
| `smtp_client/` | 2       | SMTP-клиент: отправляет письмо через SMTP-сервер                  |
| `smtp_server/` | 3       | Упрощённый SMTP-сервер на порту 2525: принимает письмо и выводит его в консоль |
| `КЛИЕНТ_ДЛЯ_ОТПРАВКИ/` (и `.zip`) | 1, 2 | Пакет для одногруппников: Courier, клиент и `ИНСТРУКЦИЯ.md` |

Нужен .NET 10 SDK.

## Задание 1. Почтовый сервер Courier

Courier Mail Server работает только под Windows, поэтому его нужно запускать на компьютере в аудитории.

1. Распакуйте `cms159.zip` и запустите `cms159\CourierMS.exe`. Когда брандмауэр спросит, разрешите доступ.
2. Щёлкните правой кнопкой по «SMTP-сервис» и выберите «Свойства». Укажите порт `25`, включите «Требовать аутентификации клиентов» и оба метода: «PLAIN, LOGIN» и «CRAM-MD5».
3. Щёлкните правой кнопкой по «Пользователи» и откройте пользователя (например, `Stud01`) или создайте нового. Задайте пароль и почтовую папку (`Mail\Mailbox\Stud01\`). В эту папку будут попадать письма для этого пользователя.
4. Адрес пользователя: `Stud01@domain.local`. Тот же адрес используется как логин для аутентификации.

## Задание 2. SMTP-клиент

Клиент подключается к серверу по TCP и выполняет SMTP-диалог по шагам. Каждая команда и каждый ответ сервера выводятся в консоль: `C:` — команды клиента, `S:` — ответы сервера.

1. Ждёт приветствие `220`.
2. Отправляет `EHLO localhost` и читает многострочный ответ `250-…/250 …`.
3. Если задан `--user`, выполняет аутентификацию методом, который поддерживает сервер. Проверяются методы по порядку: `CRAM-MD5` (пароль по сети не передаётся), затем `LOGIN`, затем `PLAIN`. В консоли пароль заменяется на `********`.
4. Отправляет `MAIL FROM:<…>`, `RCPT TO:<…>`, `DATA` (ждёт ответ `354`).
5. Передаёт заголовки `From: Test User <…>`, `To: Recipient <…>`, `Subject: Test from SMTP Client`, а также `Date` и `Content-Type` в UTF-8, чтобы русский текст отображался правильно. Затем отправляет пустую строку и текст письма. Если строка текста начинается с точки, клиент удваивает эту точку (dot-stuffing). Передача заканчивается последовательностью `\r\n.\r\n`.
6. Отправляет `QUIT` и ждёт ответ `221`.

Если сервер отвечает неожиданным кодом, клиент выводит ошибку и завершается с кодом 1.

Значения по умолчанию взяты из условия: `localhost:25`, отправитель `test@localhost`, получатель `user@localhost`.

```sh
cd razr_rasp_prog/Задание_4/smtp_client
dotnet run                                   # localhost:25, без аутентификации
dotnet run -- --port 2525                    # отправить на сервер из задания 3
```

Отправка через Courier, у которого включена обязательная аутентификация:

```sh
dotnet run -- --user Stud01@domain.local --password <пароль> --from Stud01@domain.local --to Stud01@domain.local
```

После этого в `cms159\Mail\Mailbox\Stud01\` появится файл письма. Если Courier запущен на другом компьютере, добавьте `--host <его IP>`.

Все параметры: `--host`, `--port`, `--from`, `--to`, `--subject`, `--text`, `--user`, `--password` (список выводится при неверных аргументах).

## Задание 3. Упрощённый SMTP-сервер

```sh
cd razr_rasp_prog/Задание_4/smtp_server
dotnet run                 # слушает localhost:2525
dotnet run -- --lan        # слушает все интерфейсы: к серверу могут подключиться другие компьютеры
```

По условию сервер слушает только `localhost`, и это поведение по умолчанию. Для командной работы нужен флаг `--lan`. В этом режиме сервер выведет свои адреса, например `Адрес для клиентов: 172.20.10.12 (en0)`. Сообщите одногруппникам адрес Wi-Fi-интерфейса (`en0`). Адреса `utun*` относятся к VPN и не подходят. Если macOS спросит, разрешить ли входящие подключения, нажмите «Разрешить». Порт можно сменить: `dotnet run -- 2626 --lan`.

- При подключении отправляет `220 localhost SMTP Test Server`.
- `EHLO` → `250-Hello\r\n250 HELP` (также поддерживается `HELO`).
- `MAIL FROM:<…>` → сохраняет отправителя, отвечает `250 OK`.
- `RCPT TO:<…>` → добавляет получателя, отвечает `250 OK`. Получателей может быть несколько.
- `DATA` → `354 End data with <CR><LF>.<CR><LF>`. Сервер читает строки до строки из одной точки и убирает удвоенные точки в начале строк.
- После приёма письма в консоль выводятся отправитель, получатели и всё тело письма с заголовками. Клиент получает ответ `250 OK`.
- `QUIT` → `221 Bye`, соединение закрывается.

Дополнительно:

- Сервер обслуживает несколько клиентов одновременно, каждого в своём потоке.
- Команды распознаются без учёта регистра.
- Команды в неправильном порядке получают ответ `503`, например `DATA` до `RCPT TO`. Неизвестные команды получают `500`. Также поддерживаются `RSET` и `NOOP`.
- Строки длиннее 1000 символов, письма больше 10 МБ и клиенты, которые молчат больше 5 минут, не могут занять сервер навсегда.
- Сервер останавливается по Ctrl+C.

## Работа втроём

Я запускаю сервер (задание 3), двое одногруппников запускают клиенты.

1. Отправить одногруппникам `КЛИЕНТ_ДЛЯ_ОТПРАВКИ.zip`. В архиве: Courier, клиент и `ИНСТРУКЦИЯ.md` с заданиями 1 и 2.
2. Каждый одногруппник настраивает Courier на своём Windows-компьютере и отправляет письмо в свой Courier (задания 1–2).
3. Я запускаю `cd smtp_server && dotnet run -- --lan` и сообщаю свой IP.
4. Одногруппники отправляют письмо на мой сервер: `dotnet run -- --host <мой IP> --port 2525 --from имя@localhost`. У меня в консоли появляются оба письма, их можно различить по отправителю.

## Проверка

В одном терминале запустите сервер (`smtp_server`), в другом — клиент:

```sh
cd smtp_client && dotnet run -- --port 2525
```

Клиент выведет весь диалог и строку «Письмо успешно отправлено.». Сервер выведет блок «Письмо» с отправителем `test@localhost`, получателем `user@localhost` и телом письма.

Сервер можно проверить и вручную, без клиента: `telnet localhost 2525` или `nc localhost 2525`. Дальше вводите команды из задания по одной.
